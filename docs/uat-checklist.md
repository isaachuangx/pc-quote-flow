# GUI 用户验收清单（UAT）— pc-quote-flow v0.1.0

> 本清单按**真实业务阶段**串成一条「虚构配置B」端到端场景：
> 询价·采购确认成本货源 → 销售报价 → 客户确认 → 采购执行·核实确认价 →
> 导出审批文件·管理层**合并审批**（报价合理性＋采购款项合理性，一次审批）→
> 采购下单回写实际价 → 完成。全程同一个文件、同一套虚构数字，不再按功能点分散验收。
>
> 依据：设计文档 v5 附录A/B（期望值唯一权威）、§9 流程、§13.12（R45 合并审批）。
> **全部数字为附录A虚构样例**。真实报价数据永不入库（红线1）。
> 程序**不做审批决策、不强制拦截、不做权限控制**（红线2）：低于底价仅红色警告 +
> 导出前一次确认 + 日志留痕，任何按钮都不会被禁用；状态只是备忘标签，不锁编辑。

- [ ] 「采购」tab 核对 CPU（散片）行的**含税成本单价/发票类型/供应商/平台/商品链接**
      五列**可编辑**（R43：成本与货源归采购录入）；试改任一列再改回，修改日志盖「采购视图」章。
- [ ] 切到「销售」tab：同样这五列**只读改不动**（销售只编辑部件名/型号/数量/单项利润率/客户确认）。

## 阶段2 销售报价

【角色：销售客服｜tab：销售｜业务含义：据采购确认的成本加利润报价并发客户｜状态：询价→已报价】

- [ ] 切换操作人为**销售客服**，「销售」tab 输统一利润率 **10**（成本加成模式）。
- [ ] 四数面板：**整机底价 4130.00 ／ 客户报价 4543.00 ／ 利润(不含税) 365.49 ／
      加成率 10.00% ／ 毛利率 9.09%**（B.7 行5）。
- [ ] 点「导出客户报价单」→ 保存到 `exports/` → 状态变 **已报价**，日志含导出记录。
- [ ] **脱敏检查（红线5）**：用 Excel/WPS 打开导出的客户报价单——
      无成本、无供应商、无商品链接，亦无确认价/实际价/订单号；
      再查**隐藏列、批注、文档属性**也不携带内部数据（只有部件名/型号/数量/件报价与对外信息行）。

**可选压力子项（收进本阶段，试完恢复基准再继续）：**

- [ ] 把统一利润率改为 **−5**：出现**红色**低于底价警告；三个导出按钮**仍可点击**。
      点「导出客户报价单」→ 弹"低于底价确认"对话框（**仅一次**）→ 确认后**导出成功**，
      日志摘要含"低于底价确认导出"。⚠️ **导出成功会自动保存工作文件（版本+1）——此刻磁盘上的利润率已是 −5%**。
      试完把利润率改回 **10** 并点「保存」，四数恢复上述基准（务必保存，否则下一步重开仍回到 −5%）。
- [ ] （可选）点「反算写回…」→ 目标整机报价输 **4555.55** → 预览反算加成率 ≈**10.30%** →
      点「写回」：整机报价合计**精确 4555.55**，CPU 件报价 **1246.44**（尾差仅由底价最大件吸收），
      单项利润率被清空，日志摘要含"反算写回/尾差"（B.7 行8）。
      ⚠️ 反算会留下尾差调整，**试完不要保存**。放弃这次改动、回到加成 10% 基准，推荐直接在利润率框
      **输入 10 回车**（统一利润率即回 10%、报价回 **4543.00**，最稳妥）。
      也可用「打开」重新载入 `data/虚构配置B.xlsx`，但**重开只恢复磁盘上次保存的状态**：
      它丢弃的是**未保存**改动，不会把文件重置回出厂 10%——若上一步 −5% 导出后没把 10% 存盘，
      重开回到的是 **−5% 而非 10%**（R47 澄清：这正是「重开恢复不了 10%」的原因，非程序缺陷）。
      如需彻底纯净基准，关程序后重新从 `samples/虚构配置B.xlsx` 复制到 `data/` 再打开。

## 阶段3 客户确认

【角色：销售客服｜tab：销售｜业务含义：客户接受报价，交回采购执行｜状态：已报价→客户已确认】

- [ ] （业务动作）客户同意整机报价 **4543.00**。
- [ ] 「销售」tab 逐件勾选「**客户确认**」列（9 件全勾），或直接勾表格上方的
      整单「**客户已确认报价**」勾选框（一次置全件）。二者**聚合**：全件确认 →
      状态自动变 **客户已确认**（日志多一条聚合流转）；整单框勾选态=全件是否都确认。
- [ ] 取消任一件的「客户确认」→ 状态自动回 **已报价**、整单框取消勾选；补勾后回到客户已确认。
      试完恢复**全件确认**再继续。「客户确认」列在「采购」「审阅」tab **只读**
      （确认勾选由销售客服编辑——视图编辑权划分，不是身份门禁，红线2）。
- [ ] 客服把文件交回采购（微信/邮件传 xlsx 即可；本机验收继续用同一个打开的文件）。

## 阶段4 采购执行·核实确认价

【角色：采购｜tab：采购｜业务含义：下单前逐件核价，填确认价——**确认价在客户确认后、审批前填**｜状态：客户已确认】

> **先分清两列（R47 澄清，关键）**：
> - **「确认价」列**＝本阶段要填的、采购执行中核实的当前采购价。它**只抬高「确认后底价」、进审批摘要，
>   不改客户报价**——客户报价 Q 只由「含税成本单价」列算。填确认价 2000 → Q 仍 **4543.00**、确认后底价 **5260.00**
>   → **直接**红字「已低于底价」（5260＞4543），**无需反算**。
> - **「含税成本单价」列**＝报价阶段定的原始成本（CPU 仍 1000）。**改它才会抬高客户报价**（按当前利润率重算）。
> 本阶段主路径填的是 **「确认价」**，**不是**「含税成本单价」——别填错列（填错列会看到报价被抬高，那是另一回事，见末条可选说明）。

- [ ] 切换操作人为**采购**，「采购」tab **右键** CPU（散片）行"商品链接"单元格 →
      「打开链接」→ 浏览器打开逐件核价（双击=编辑链接，右键=打开）。
- [ ] 给 CPU（散片）填**确认价 2000**（填「确认价」列，含税成本单价保持 1000 不动）、**确认发票类型：普票**（其余 8 件不填，回退成本价）。
- [ ] **自动撤销确认（R46）**：确认价属报价/成本字段，一变即自动撤销 CPU 件的
      「客户确认」（日志摘要含"客户确认已撤销"），聚合破坏 → 状态回 **已报价**。
      切「销售」tab 重新勾选 CPU 件「客户确认」（业务上：核价结果与客户重新确认）→
      全件再次聚合 → 状态回 **客户已确认**，再继续阶段5。
      （改 数量/含税成本单价/单项利润率/部件名/型号/发票类型 同样触发撤销；
      改 供应商/平台/商品链接/采购日期/订单号/备注 不触发。）
- [ ] **立即**出现红字"**已低于底价，请按公司流程审批**"（纯 GUI 录入即生效，无需重新保存/打开）；
      确认后底价显示 **5260.00**（=3000+2000×1.13）＞ 客户报价 4543.00；
      **导出按钮仍可用，程序不拦截**（红线2）。
- [ ] 真实利润面板显示 **−634.51**（红色，负利润警告；=4543/1.13−(3000/1.13+2000)）。
- [ ] 切到「销售」tab：确认价/确认发票类型列**只读**（采购字段销售改不动）。

**可选说明（理解「改成本会抬高报价」，R47 澄清——合理行为，非缺陷）：**
若改的是 **「含税成本单价」** 1000→2000（而非「确认价」）：客户报价会按当前 10% **自动抬高到 5786.00**、
该件客户确认自动撤销、整单回已报价；此时报价 5786 ＞ 底价 5260，**没有红字**（成本涨→报价跟涨，合理）。
若要复现「客户已同意 4543、但采购成本上涨」的低于底价场景，用「反算写回」把整机报价写回 **4543.00**
→ 确认后底价 5260 ＞ 4543 → 红字「已低于底价，请按公司流程审批」出现。
**主路径填「确认价」即可直接看到红字（Q 不变），不必走改成本这一步。**

## 阶段5 导出审批文件·管理层合并审批

【角色：销售客服导出→管理层审批｜tab：审阅｜业务含义：**一次合并审批＝报价阶段合理性＋采购阶段款项合理性**｜状态：客户已确认→待审批→采购中】

- [ ] （销售客服或采购均可）点「导出审批文件」→ 保存到 `exports/` → 状态变 **待审批**。
      此时审批文件**已含确认价 2000 与采购侧汇总**（R45：确认价先于审批）。
- [ ] 切换操作人为**管理层**，用「打开」载入刚导出的审批文件 → 切「审阅」tab：
      **全列恒只读**（防误改，任何状态下都改不动数据是正常的）。
- [ ] 用 Excel/WPS 打开审批文件看「审批摘要」sheet（两列键值）：
      **报价侧**——整机底价 **4130.00** ／ 整机报价 **4543.00** ／ 利润额(不含税) **365.49** ／
      加成率 **10.00** ／ 毛利率 **9.09**；
      **采购侧汇总（确认价口径，B.5）**——确认后底价 **5260.00** ／ 确认成本合计(含税) **5000.00** ／
      有效不含税成本 **4654.87** ／ 真实利润(不含税) **−634.51** ／ 报价时预期利润(不含税) **365.49** ／
      利润侵蚀 **是** ／ 负利润警告 **是** ／ 报价低于确认后底价 **是**。
- [ ] **合并审批判断**：既看报价合理性（两率/利润），也看采购款项合理性
      （确认成本 5000.00 已高于报价口径、真实利润为负）——按公司流程决定同意/驳回/需调整。
- [ ] 在「审阅」tab 点「填写审批意见」→ 结论选"**同意**"+ 填意见 → 确认后状态变 **采购中**，
      审批记录 +1，修改日志含"审批记录"条目。（若选驳回/需调整 → 退回已报价，可重新报价再审，多轮只增不改。）
- [ ] 说明：**"采购中"只是备忘标签，不锁定任何编辑**（红线2 无权限门禁）；
      程序只记录结论，审批决策归公司流程/ERP。

## 阶段6 采购下单回写

【角色：采购｜tab：采购｜业务含义：批准后下单，回写实际成交价与订单信息｜状态：采购中→已完成】

- [ ] 切换操作人为**采购**，点顶部「采购」tab——仍是**同一个配置B**，无需重开程序、无需换样例。
- [ ] （业务动作）按批准的款项下单。回写 CPU（散片）行：**实际成交价 1050**、
      **实际发票类型：普票**、**订单号**（虚构即可）、**采购日期**。
- [ ] 真实利润变为 **315.49**（=4543/1.13−(3000/1.13+1050)），出现橙色**侵蚀提示**
      「真实利润低于预期利润：采购成本侵蚀了利润」（315.49 < 报价时预期 365.49）。
      **侵蚀的比较基准是报价时原始成本口径（CPU 1000 → 预期 365.49），不是确认价 2000**：
      实际价 1050 比原报价成本 1000 贵 50，故真实利润比预期少 50 → 侵蚀。
      相对确认价 2000 那步（真实利润 −634.51）利润已大幅回升，**负利润红字消失**（315.49＞0）。
- [ ] **两个底价标签要分清（R48 探针实证澄清）**：
      「确认后底价（确认价口径）」**保持 5260.00**（确认价 2000 未变，该标签只看确认价）；
      「有效价底价 B'（实际→确认→成本）」变为 **4186.50**（有效价取实际价 1050，B.5）。
      红字「已低于底价，请按公司流程审批」**仍然显示**——它绑定确认价口径底价 5260＞4543，
      不因填实际价而消失（是否应消失属设计取舍，见「常见操作答疑」）。**不阻止任何操作**。
- [ ] **报价 Q 不变（仍 4543.00）、整单状态保持「采购中」**：实际成交价不进报价公式
      （Q 只由含税成本单价算）；状态聚合降级只在「客户已确认」态触发，采购中不降级。
      但该件「客户确认」标志会被撤销（实际成交价属自动撤销字段），日志含「客户确认已撤销」。
- [ ] 点「采购」tab 顶部的「**完成采购**」图标按钮（对勾图标，tooltip"完成采购（状态→已完成）"）
      → 状态变 **已完成**，日志 action「完成采购」。非常规流转不拦截只留痕（红线2）。

**可选压力子项（废弃/恢复图标，试完恢复已完成再继续）：**

- [ ] 点工具栏**垃圾桶图标**（tooltip"废弃此报价单（状态→已废弃）"）→ 状态变 **已废弃**，
      日志 action「废弃报价单」；按钮图标随即变**恢复图标**（tooltip"恢复（状态→已报价）"）。
- [ ] 再点一次 → 状态回 **已报价**（已废弃→已报价 属非常规流转，日志加"非常规流转"前缀，
      不拦截）；图标切回垃圾桶。任何状态下按钮都**不会被禁用**。

## 常见操作答疑

- **状态会不会锁住编辑？** 不会。询价/已报价/客户已确认/待审批/采购中/已完成 都只是备忘标签；
  「销售」「采购」tab 在任何状态下都可编辑各自的可编辑列，「审阅」tab 始终只读（红线2）。
- **审批同意后怎么做采购回写？** 点「采购」tab，用同一个文件继续即可（阶段6），不必换样例或重启。
- **不关程序能换/再加一个样例吗？** 能：① 工具栏「打开」载入另一份文件（先保存当前文件）；
  ② 「审阅」tab「对照打开」另开新窗口载入第二份文件并排对照；③ 再双击一次 exe 开第二个独立实例。
- **商品链接归谁填？** 采购（R43）：采购 tab 双击编辑、右键「打开链接」核价；销售 tab 只读、双击打开看货源。
- **客户确认后改价会怎样？** 报价/成本字段（部件名/型号/数量/含税成本单价/发票类型/单项利润率/
  确认价/确认发票类型/实际成交价/实际发票类型）一变，该件「客户确认」自动撤销并留痕；
  全件不再都确认时状态从客户已确认回已报价。改统一利润率/算法模式/反算写回 → **全件**撤销。
  供应商/平台/链接等非价格字段不触发。重新勾选即重新聚合。
- **确认价 2000 填哪个样例？** 配置B 的 CPU（散片）行（原 1000 普票）。配置A 的 CPU 是 2000 专票，不要混。
- **三个价格列各管什么（R48 澄清，关键）**：①「含税成本单价」＝报价时成本，**改它才会抬报价 Q**；
  ②「确认价」＝阶段4 采购核价，只抬「确认后底价（确认价口径）」、**不改 Q**；
  ③「实际成交价」＝阶段6 下单回写，只进「有效价底价 B'/真实利润」、**不改 Q**。
  三者都属自动撤销字段（改了会撤销该件客户确认），但只有①改报价。
- **侵蚀提示相对什么比？** 相对**报价时原始成本**算出的预期利润（配置B＝365.49），不是相对确认价。
  实际采购价高于原报价成本就侵蚀（哪怕比确认价低）；低于原报价成本则不侵蚀。
- **填了实际价，红字「已低于底价」为什么还在？** 该红字绑定「确认后底价（确认价口径）」（确认价 2000→5260＞4543），
  代表「报价低于采购确认的款项底线，需公司审批」，是审批阶段的提醒；实际成交价更低不会改变确认价口径底线。
  若你希望「实际采购价已低于报价时红字自动消失」，属行为调整，需另行确认方案再改（现保持不消失）。
