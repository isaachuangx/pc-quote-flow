## 1. 背景与定位

公司销售组装电脑，采购有两个渠道：

- 渠道A：人工在淘宝/京东逐件采集商家报价，成本更低，但发票类型混杂（专票/普票/京东专票）；
- 渠道B：单一供应商整单报价，全专票，略贵但抵扣链完整。

核心痛点：**普票进项不能抵扣，导致"采购成本价"≠"最低可卖价"**。
例如虚构配置B：采购含税 4000 元（含 CPU 1000 元普票），增值税口径的 0 毛利平衡点是
4130.00 元，差出的 130 元 = 1000×13%。销售/客服不懂这套算法，照成本加点报价可能实际亏损。

报价列表在四个角色间流转：询价定价（采购/老板）→ 销售报价（销售/客服）→ **管理层审阅（审批辅助）** → 采购执行（采购操作员）。
目前靠手工表格+口头传递，底价靠人脑、无状态记录、无采购回写。

**定位边界（用户确认）**：本程序是流程优化辅助工具——自动算底价与客户报价、向客户展示报价、
记录流转状态与采购回写、为管理层审阅提供完整数据与合理性摘要。
**报价审批、折扣权限等由管理层/公司 ERP 流程决定，程序不做审批决策、不做强制拦截、不做权限控制**；
低于底价只给醒目警告并留痕；管理层可在程序内记录审批结论与意见（也可只在 ERP 审批），程序仅记录展示。

## 2. 目标（做什么）

1. 内置增值税规则，自动算逐件与整机的**平衡点报价（底价）**。
2. 输入利润率 → 自动算客户报价。两种算法开关切换：**成本加成（默认）**与销售毛利率。
3. **统一毛利率**（整机一个比例）与**单项毛利率**（逐件覆盖）并存；整机报价 = 各件报价之和。
4. **反算**：输入客户报价 → 显示加成率、毛利率、利润；谈妥的价格可写回为正式报价并导出。
5. 每个报价同屏显示四个数：客户报价、利润额（不含税）、加成率、销售毛利率。
6. 角色视图：销售视图（部件配置＋利润率＋底价/报价计算；成本/发票/供应商/平台/链接由采购录入，销售只读展示）、采购视图（含税成本/发票/供应商/平台/商品链接录入＋确认价/实际价回写）、**审阅视图（管理层，只读全字段+审批摘要+结论记录）**。视图是纯 UI 切换，无权限。
7. 状态记录：询价 → 已报价 → 客户已确认 → **待审批** → 采购中 → 已完成（可回退、可废弃；审批驳回退回已报价）。状态是流转备忘，不是权限门禁，变更全部写日志。
8. **低于底价警告（仅提示，不拦截）**：报价低于底价时红色醒目警告；导出时弹一次确认提示；写入日志。审批交管理层/公司流程。
9. 采购回写：采购员填实际成交价/实际发票类型 → 程序重算真实利润，低于预期时提示（不阻止操作）。
10. 一键导出三种文件：**客户报价单**（整机总价+可选明细，绝不带成本/供应商/链接）、**审批文件**（全部内部数据+合理性摘要，给管理层）、**采购单**（确认价+发票+链接+订单号栏）。
11. 报价有效期字段（电商价格时效性强，过期提示）。
12. 同配置两渠道列表并排比价（v1 简化为两份文件对照打开，v1.1 做对比视图）。
13. 数据文件就是 .xlsx：微信/邮件照传，没装程序的人用 Excel/WPS 也能看数、存档。
14. **管理层审阅辅助**：审批摘要（底价/报价/利润/利润率/普票税额影响/单项利润率分布/是否低于底价/有效期）+ 全部件明细 + 修改日志；可记录审批结论（同意/驳回/需调整）与意见，写回文件并留痕。
15. **操作人身份绑定（v4）**：每台电脑本机登记姓名+角色（自动读取 Windows 账户作锚点）；每次保存/导出/状态变更/审批记录自动盖章操作人、机器、Windows账户、视图、时间、版本；只增不改的修改日志；导出文件携带导出人/导出时间/来源版本；共用电脑可快速切换操作人。

## 4. 反目标（做成这样就算失败）

- 程序写坏 Excel 文件或丢数据（保存原子化：先写临时文件再替换，保留上一版备份）。

## 8. 税务与报价计算规则

记专票件含税价合计 S，普票件含税价合计 P（普票含"普通发票"，京东专票按专票）。

- 不含税成本 C = S/1.13 + P
- **整机底价 B = S + P×1.13**（= 1.13×C）
  - 专票件底价贡献 = 其含税价；普票件底价贡献 = 含税价×1.13
- 底价口径应缴增值税 = P×13%
- 成本加成 r：**报价 Q = B×(1+r)**
- 销售毛利率 m：**报价 Q = B÷(1−m)**
- 单项利润率：对每件底价贡献分别套公式得 Q_i，整机 Q = ΣQ_i；统一利润率 = 全部件同比例。
- 显示口径（我的决定）：
  - 加成率 = (Q−B)/B；销售毛利率 = (Q−B)/Q（含税比与不含税比相等，已验证）
  - **利润额按不含税显示 = (Q−B)/1.13**（增值税不是收入；如虚构B加成10%含税价差 413 元，真实入账利润 365.49 元，毛利率不变）
- 反算：输入 Q → 加成率、毛利率、利润额同上；可写回（见 §13）。
- 采购回写后：用实际成交价/实际发票类型重算 C'、B'、真实利润 = Q/1.13 − C'，与报价时预期利润对比，低于预期提示、低于 0 红色警告（均不阻止操作）。
- 小规模模式（预留配置）：底价 = 含税成本×(1+征收率)，利润=(Q/(1+征收率)−含税成本)，v1 不实现界面仅留参数。

### 附录B：数学计算逻辑规范（v5 新增，供人工核算与学习）

> 用途：① 构建完成后，用户/财务按 **B.7 期望值总表** 人工核算程序计算是否正确；② 不理解计算逻辑时，按 B.1→B.6 顺序阅读公式与算例；③ 实现与测试以本附录为**唯一数学口径**（`scripts/verify_math.py` 独立重算比对，见 §14）。所有数字为虚构样例，与附录A一致。

#### B.1 符号与舍入规则

| 符号 | 含义 |
|---|---|
| t | 增值税率，一般纳税人销售货物 13%（v1 固定；小规模仅预留参数） |
| p_i, n_i | 第 i 件含税成本**单价**、数量；行总价 = p_i×n_i |
| S | 全部**专票**件行总价之和（京东专票归一化为专票） |
| P | 全部**普票**件行总价之和（"普通发票"归一化为普票） |
| f_i | 第 i 件底价贡献（全精度） |
| C | 不含税成本 = S/(1+t) + P |
| B | 整机底价（含税、增值税口径 0 毛利）= S + P×(1+t) |
| Q | 客户报价（含税）= Σ 舍入后件报价 q_i |
| r / m | 成本加成率 / 销售毛利率；r_i 为件率（单项覆盖优先，否则统一率） |

**舍入规则（钉死）**：
- 全程 `Decimal`；**中间量全精度不舍入**；仅在显示/输出时 `ROUND_HALF_UP`（四舍五入）到分（0.01）。
- 件报价 q_i 由**全精度**件底价 f_i 算出后再舍入；整机报价 Q = Σq_i（保证明细合计=总价）。
- 整机底价 B = round(Σf_i)；百分比显示保留 2 位小数。
- 客户报价单导出可选"取整到元"（默认关；开启时整机价四舍五入到元并省略明细表）。
- ⚠️ **人工核算注意**：用"显示的已舍入值"复算，可能与程序差 ≤0.01 元（程序用全精度中间量），属正常，见 B.6 例7。

#### B.2 底价（0 毛利平衡点）

```
专票件:  f_i = p_i × n_i
普票件:  f_i = p_i × n_i × (1+t)
B = S + P×(1+t)        C = S/(1+t) + P        恒等式: B/(1+t) = C（精确成立）
底价口径应缴增值税 = P × t
```

**推导（为什么普票要 ×1.13）**：以含税价 B 卖出，销项税 = B×t/(1+t)；专票采购进项税 = S×t/(1+t)，普票**无进项可抵**。令 B = S+P×(1+t)，则销项税 = S×t/(1+t) + P×t，应缴增值税 = 销项−进项 = **P×t**；同时不含税收入 B/(1+t) = S/(1+t)+P = C，毛利恰为 0。大白话：普票那部分采购的 13% 增值税抵不回来，必须从客户身上"赚回来"，所以底价比采购价高 13%。全专票时 P=0 → **底价 = 采购合计**。

#### B.3 客户报价（两种算法，默认成本加成）

```
成本加成:   q_i = round( f_i × (1 + r_i) )
销售毛利率: q_i = round( f_i ÷ (1 − m_i) )
整机 Q = Σ q_i
四个数:
  利润额(不含税) = round( (Q − B)/(1+t) )   （恒等于 Q/(1+t) − C）
  加成率 = (Q − B)/B        毛利率 = (Q − B)/Q
```

- 含税口径与不含税口径算出的两率**相等**（分子分母同除 1.13）。
- 同一比例值两种模式报价不同（毛利率模式更高）；理论换算 m = r/(1+r)，r = m/(1−m)（舍入前）。
- 例：r=10% → 理论毛利率 9.09%；m=10% → 理论加成率 11.11%。

#### B.4 反算与写回

```
输入目标整机价 T:
  加成模式反解   r* = T/B − 1
  毛利率模式反解 m* = 1 − B/T      （全精度）
写回规则:
  1) 统一率 ← r*/m*，模式 ← 当前模式
  2) 清除全部单项利润率覆盖
  3) 重算件报价；舍入尾差 δ = T − Σq_i 加到**底价最大件**的报价调整值
     → 保证 Σq_i 精确等于 T；日志记"反算写回"与尾差值
```

#### B.5 采购回写与真实利润

```
有效价回退链: 实际成交价 → 确认价 → 报价时成本价（发票类型同链回退）
cost_excl(有效价): 专票 = 行总价/(1+t)；普票 = 行总价
C' = Σ cost_excl(有效价)        确认后底价 B' = Σ f_i(有效价)
真实利润 = round( Q/(1+t) − C' )     （Q 一经发出固定，不随采购变）
预期利润 = round( (Q − B)/(1+t) )    （报价时成本口径）
真实 < 预期 → 侵蚀提示；真实 < 0 → 红色警告；均不阻止任何操作
```

三层价格并列显示：报价时底价 B ／ 确认后底价 B' ／ 客户报价 Q。

**审批摘要采购侧汇总（R45，合并审批＝报价合理性＋采购款项合理性）**：审批文件「审批摘要」sheet 在报价侧 13 字段之后追加采购侧汇总 8 字段（两列键值，金额 str、bool→是/否）：

| 字段 | 口径 |
|---|---|
| 确认后底价 | `pricing.actuals` 的有效底价 floor——审批阶段实际价未填，回退链落到确认价，故＝确认后底价（有效价 B' 口径） |
| 确认成本合计(含税) | Σ(确认价??成本价)×数量（附录B 单价×数量口径；确认价为空回退成本价） |
| 有效不含税成本 | `pricing.actuals` 的 C' |
| 真实利润(不含税) | `pricing.actuals` 的 real_profit |
| 报价时预期利润(不含税) | `pricing.actuals` 的 expected_profit（成本价口径） |
| 利润侵蚀 | real_profit < expected_profit → 是/否 |
| 负利润警告 | real_profit < 0 → 是/否 |
| 报价低于确认后底价 | 整机报价 < 确认后底价 → 是/否 |

实现消费 `pricing.actuals`（B.5 权威回退链 实际→确认→成本）与 `pricing.price_doc`，**不新造公式**；eroded/negative/below 仅标记不拦截（红线2）。

算例（配置B：CPU散片 1000 普票＋其余 8 件专票合计 3000，成本加成 10%；CPU 确认价 2000、确认发票普票，实际价未填）：
- 确认后底价 = 3000 + 2000×1.13 = **5260.00**；确认成本合计(含税) = 3000 + 2000 = **5000.00**；
- C' = 3000/1.13 + 2000 = **4654.87**；真实利润 = 4543/1.13 − C' = **−634.51**；预期利润 **365.49**；
- 利润侵蚀＝**是**（−634.51 < 365.49）；负利润警告＝**是**；报价低于确认后底价＝**是**（4543.00 < 5260.00）。
- 续：采购下单回写 CPU 实际成交价 1050（普票）后，有效价取实际价：真实利润 = 4543/1.13 − (3000/1.13+1050) = **315.49**，有效底价 = 3000 + 1050×1.13 = **4186.50**（4543.00 > 4186.50，不再低于；侵蚀仍是，315.49 < 365.49）。

#### B.8 边界与未含项（防止核算误读）

- v1 税率固定 13%（一般纳税人）。小规模模式仅预留参数：底价 = 含税成本×(1+征收率)，利润 = Q/(1+征收率) − 含税成本；v1 不做界面。
- 报价为"增值税口径 0 毛利 + 利润"，**未含**装机人工、运费、包装、售后预留。
- **附加税费未含**（城建税+教育费附加+地方教育附加 ≈ 应缴增值税×12%，各地略有差异）。若需含附加的现金保本口径（财务参考，v1 不实现）：不含税保本价 = (C − 0.12×进项税)/(1 − 0.12×t)，其中进项税 = S×t/(1+t)。配置B例：进项税 345.13，不含税保本 ≈ **3670.71**，含税 ≈ **4147.91**（高于 B=4130.00 的部分即附加税费负担）。

1. 询价·采购确认成本货源：客户向销售/客服询价 → 销售/客服在未知成本前转采购确认渠道与成本 → 采购确认货源后录入价格、发票、供应商、平台、链接（R43）→ 程序算底价 → 成本发回销售/客服 → 保存 v1（状态:询价，创建人盖章）。
2. 销售报价：打开 → 输统一或单项利润率（据采购确认的成本加利润报价）→ 看四个数 → （如需）反算写回谈妥价 → 导出客户报价单 → 状态:已报价 → 传回（修改人/导出人盖章）。
3. 客户确认：客户接受 → 销售视图逐件勾「客户确认」或勾整单「客户已确认报价」（二者聚合：全件确认→状态:客户已确认；任一撤销→回已报价）→ 客服把文件交回采购。**自动撤销（R46）**：报价/成本字段（部件名/型号/数量/含税成本单价/发票类型/单项利润率/确认价/确认发票类型/实际成交价/实际发票类型）一变即撤销该件确认并留痕；改统一利润率/算法模式/反算写回→全件撤销。供应商/平台/链接等非价格字段不触发。
4. 采购执行·核实确认价：采购视图逐件核价（右键「打开链接」打开核对）→ 填确认价/确认发票（**确认价在客户确认后、审批前填**；确认价变更会自动撤销该件客户确认，需销售与客户重新确认后补勾）→ 确认后底价 > 客户报价时红字警告"已低于底价，请按公司流程审批"（不拦截）。
5. 导出审批文件：导出审批用文件（完整内部数据+审批摘要，**含确认价与采购侧汇总**，R45/附录B.5）→ 状态:待审批 → 传管理层。
6. 管理层合并审批：程序打开审批文件 → 审阅视图看摘要与明细（可对照另一渠道文件）→ **一次合并审批＝报价阶段合理性＋采购阶段款项合理性** → 作出审批决定（公司流程/ERP）→ 可在程序内记录结论与意见（审批人盖章）→ 文件传回。同意 → 状态:采购中，交采购员；驳回/需调整 → 退回已报价，销售重新报价后再审。
7. 采购下单回写：按批准的款项下单 → 回写实际成交价/发票/订单号/采购日期 → 程序重算真实利润并提示（若侵蚀）→ 点采购视图「完成采购」图标按钮 → 状态:已完成（回写人盖章）。任意阶段可点工具栏废弃/恢复图标按钮：未废弃→已废弃（action 废弃报价单），已废弃→已报价（action 恢复报价单，非常规流转只留痕不拦截）；icon/tooltip 随状态切换，按钮恒可用。

## 13. 实现者审查结论与补充决定（2026-11-18）

独立审查提出 7 个问题，处理如下；v3 管理层审阅、v4 身份绑定的细节由我拍板（用户可否决）。

### 用户裁定

- **保护强度**（v2）：不做审批/拦截/口令/管理员角色。低于底价仅红色警告+导出确认+日志；审批走公司 ERP/上司流程。
- **数据边界**（v2）：报价数据永不入仓库；文档与测试夹具全部虚构化（附录A），真实价格仅本机验证。
- **管理层审阅环节**（v3）：客户确认后、采购执行前，导出审批用 Excel 报价文件 → 管理层用程序读取审阅，辅助判断报价合理性与采购审批。

### 我的决定（实现者可直接采纳，用户可否决）

1. **三层价格口径**：客户报价 Q 一经发出即固定。采购填确认价后，并列显示"报价时底价"与"确认后底价"；确认后底价 > Q 时红色提示"已低于底价，请按公司流程审批"，**不阻止任何操作**。预期利润 = 报价时利润（报价时成本口径）；真实利润 = Q/1.13 − 实际不含税成本；真实 < 预期即提示，< 0 红色警告。
2. **反算可写回**：输入谈妥的整机价 → 按当前算法模式反解统一利润率并套用全部件，清除单项利润率覆盖（写日志），随后可正常导出。
3. **导入范围**：v1 只读写程序自有 xlsx 格式，不做旧手工表迁移；"导入"即打开程序生成的文件。
4. **数量口径**：含税成本列 = 单价；一切计算按 单价×数量 的行总价口径。
5. **舍入策略**：Decimal 全精度中间量；件报价四舍五入到分；整机报价 = 舍入后件报价之和（保证明细合计=总价）；底价显示舍入到分；客户报价单导出可选取整到元（默认关）。验收按此口径分级断言。
6. **状态记录**：允许回退（客户拒绝→已报价/询价；审批驳回→已报价）；任意状态可废弃；导出客户报价单后自动置"已报价"，导出审批文件后自动置"待审批"；状态不做权限门禁，所有变更记录操作人+时间。
7. **操作人身份绑定（v4 扩充）**：首次运行登记姓名+角色（采购/销售客服/管理层），自动预填 Windows 用户名；存 `%APPDATA%\pc-quote-flow\profile.json`（按 Windows 登录用户隔离，不进报价文件）。每次写操作盖章 姓名+角色+机器名+Windows账户+当前视图+时间+版本，日志只增不改。共用电脑工具栏快速切换操作人（写日志）。导出文件总览带导出人/导出时间/来源版本。保存记内容哈希，打开校验不一致→警告"文件曾在程序外被修改"并留痕。**性质：自报身份+OS锚点，事后追责（审计），非事前权限拦截**——冒用姓名会被日志中的 Windows账户/机器名暴露不一致，管理层审阅可查；与 v2"不做权限"裁定一致。
8. **审批文件**（v3）：专用导出 `配置名_客户_审批_vN.xlsx`，含全部内部数据+审批摘要；与客户报价单（脱敏）、采购单（采购字段）三种导出严格隔离。
9. **审批结论记录可选**（v3）：管理层可在审阅视图记录结论+意见（写回文件），也可只在 ERP 审批、程序留空；程序仅记录展示，不以审批状态作为操作门禁。
10. **审阅视图只读**（v3）：默认只读防误改，仅审批意见区可写；摘要内容=底价/报价/利润/两率/普票税额影响/单项利润率最高最低/是否低于底价/有效期/版本。
11. **R43 按角色全面收口（用户裁定）**：真实流程为客户向销售/客服询价 → 销售/客服转采购确认渠道与成本 → 采购确认货源（含商品链接）后把成本发回销售/客服 → 销售/客服据成本加利润报价。因此成本/发票/供应商/平台/商品链接归采购编辑，销售只读；销售编辑部件名/型号/数量/单项利润率；链接采购双击编辑＋右键「打开链接」、销售只读双击打开。这是视图可编辑列划分（UI 编辑权），不是权限门禁——状态不锁编辑、低于底价仅红警告＋导出前一次确认＋日志（红线2 仍生效）。
12. **R45 合并审批与采购侧汇总（用户裁定）**：审批＝**一次合并审批**（报价阶段合理性＋采购阶段款项合理性），不做两次审批。**确认价先于审批**：客户确认后、导出审批文件前由采购在采购视图填确认价/确认发票（§9 流程第4步）。审批文件「审批摘要」sheet 在报价侧 13 字段后补**采购侧汇总 8 字段**（附录B.5：确认后底价/确认成本合计含税/有效不含税成本/真实利润/报价时预期利润/利润侵蚀/负利润警告/报价低于确认后底价），消费 `pricing.actuals`（B.5 回退链）不新造公式；审批阶段实际价未填故有效价＝确认价。状态仍只是备忘标签、不拦截（红线2）；审阅视图恒只读（第10条不变）。UAT 清单按真实业务阶段整体重写（docs/uat-checklist.md：询价→报价→客户确认→核实确认价→合并审批→下单回写→留痕）。
13. **R46 客户确认与图标状态动作（用户裁定）**：① 逐件「客户确认」勾选列（销售视图可编辑，采购/审阅只读——视图编辑权划分沿用 R43，不是身份门禁）＋销售视图整单「客户已确认报价」勾选框，二者**聚合**：全件确认→状态客户已确认，任一撤销→回已报价（仅状态实际变化时 transition 留痕）。② **自动撤销**：报价/成本字段（部件名/型号/数量/含税成本单价/发票类型/单项利润率/确认价/确认发票类型/实际成交价/实际发票类型）值确实改变→撤销该件确认并在摘要留痕；统一利润率/算法模式/反算写回→全件撤销；供应商/平台/商品链接/采购日期/订单号/备注不触发。客户可能改配置（如 Intel CPU 太贵换 AMD 再报价），确认必须随报价失效。③ **图标状态动作按钮**（Qt 内置标准图标，icon-only＋tooltip，驳回状态下拉菜单方案）：采购视图「完成采购」→已完成（action 完成采购）；工具栏废弃/恢复**单按钮切换**→已废弃/已报价（action 废弃报价单/恢复报价单），icon/tooltip 随状态切换。④ 客户确认只是**状态标签＋聚合**，不改 pricing/tax 计算（附录B 定价口径不动）；非常规流转不拦截只留痕、按钮恒不 disable（红线2）；新增独立字段 customer_confirmed，采购侧遗留「价格已确认」confirmed 不动；旧文件缺「客户确认」列平滑迁移默认未确认；审批文件经 store 自动带新列，客户单/采购单显式字段集不动（红线5）。
14. **R47 逐件勾选可点性修复与清单措辞澄清（UAT 反馈）**：① 修复逐件「客户确认」单元格鼠标点不动的两处缺陷——`QuoteTableModel.flags` 对可编辑的 customer_confirmed 列补 `Qt.ItemIsUserCheckable`（缺它委托不响应点击，仅 setData 程序化可写）；`setData` 的 CheckStateRole 分支用 `Qt.CheckState(value) == Qt.Checked` 归一（委托鼠标路径传 int 2，PySide6 严格枚举 `2 == Qt.Checked` 为 False 会写成「否」空操作；R46 测试只传枚举故漏检）。采购/审阅该列不在编辑白名单→无 UserCheckable flag、只读不可点（视图编辑权，非身份门禁，红线2）。新增 flags 断言＋真实鼠标单击端到端＋int CheckState 三条测试钉死。② 清单措辞澄清（不改逻辑）：阶段2 说明导出成功会自动保存工作文件（版本+1），「打开」重开只恢复磁盘上次保存态、不重置回出厂 10%，恢复基准推荐利润率框输入 10；阶段4 明确「确认价」列只抬确认后底价、不改客户报价（填 2000→Q 仍 4543、确认后底价 5260→直接红字），改「含税成本单价」才抬高报价（成本 2000→Q 5786、无红字，反算写回 4543 才红字，合理非缺陷）。定价口径（附录B）不动。

## 14. 实现质量门禁（v5 新增，用户要求）

1. **门禁触发条件**：每完成一个功能/模块任务、**任何 bug 修复后（含测试/UAT/自检中发现的 bug，无论改动多小）**、每次 commit/push 前、打包/打标签前。除本任务测试外必须跑完整门禁：① 全量回归 `pytest tests/ -v` 全绿；② `python -m pc_quote_flow --selftest`（UI 任务起）；③ **独立数学交叉核对** `scripts/verify_math.py`——不导入程序计算函数，用 Decimal 按附录B独立重算 B.7 期望值总表并与程序输出逐项比对；④ 任何失败先排障修复，再重跑全部门禁，全绿才提交；门禁结果记入提交说明。
2. 构建完成后生成 `docs/math-verification-report.md`（独立重算 vs 程序输出对照表），交用户/财务按附录B.7 **人工核算**；人工核算通过 + GUI UAT 通过后才打 tag v0.1.0。
3. 附录B 是计算的唯一口径；实现、测试、文档数字如有冲突，以附录B为准并回改另两处。
4. 本门禁与红线已写入仓库根 **`AGENTS.md`（仓库级开发规则）**，任何 agent/开发者进入本仓库必须遵循；bug 修复须先写复现失败测试再修（TDD），修复后重跑全部门禁；子代理返回后控制者亲自重跑门禁核实（自报≠事实）。
